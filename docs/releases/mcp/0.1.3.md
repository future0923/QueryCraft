# MCP 0.1.3 (4)

## 中文
- 修复 DATABASE()/VERSION() 等上下文函数及指定库完整访问的 DDL 误拦截；按真实跨库读写目标检查对象覆盖、工具开关和精确确认。
- 统一 Redis 逻辑库名称身份，修正 Elasticsearch 多目标与 Kafka 目标 Topic 的权限判断；发现与委托入口沿用同一授权链路。
- 移除全局权限上限；对象/数据库、连接、分组依次继承，明确设置的最细一级优先，全部未设置时默认只读。旧全局 mode 字段不再生效，重新保存时移除。
- SSH 命令、文件操作和本机脚本库不再依赖全局完整访问；账号授权、工具开关和操作确认仍分别生效。
- 新增本机常用 Shell 脚本库，MCP 支持分页查询、保存、修改和删除；以版本检查防止覆盖，保存不会执行脚本。
- 新增基于可独立更新的 libssh2 插件的 SSH 工具，复用本机账号与独立授权。
- 支持命令、SFTP 文件管理、后台任务及传输进度与结果查询；任务与传输仅通过 MCP 使用。
- 支持本机 SSH Agent、最多四级跳板和逐跳失败诊断；凭据仍由本机安全存储管理。
- 新增 runtime_info，区分实际加载与已安装版本，并提示更新后重新连接客户端。
- 默认 stdio，远端无需安装 Python、Node 或专用代理；不会自动重放结果不确定的命令，不支持断点续传。

## English
- Fixes excessive restrictions on context functions such as DATABASE()/VERSION() and scoped full-access DDL. Authorization follows actual cross-database targets, object overrides, tool switches and exact confirmation.
- Canonicalizes Redis logical database identities and fixes Elasticsearch multi-target and Kafka target-topic checks. Discovery and delegated calls share authorization rules.
- Removes the global permission ceiling. Explicit object/database access overrides connection access, then group access, with read-only as the final default. Legacy global mode is ignored and removed on the next save.
- Removes the global full-access gate from SSH operations and local script CRUD while retaining per-account grants, tool switches and operation confirmations.
- Adds a local saved Shell script library with MCP CRUD, bounded reads and revision checks; saving never executes source.
- Adds SSH tools through the independently updated libssh2 plugin, sharing local accounts and explicit per-account grants.
- Supports commands, SFTP management, background tasks and retained transfer progress/results through MCP.
- Adds local SSH Agent, up to four jump hosts and per-hop diagnostics; credentials remain in local secure storage.
- Adds runtime_info to distinguish loaded and installed versions and indicate when clients must reconnect.
- Defaults to stdio with no remote Python, Node or agent installation. Uncertain commands are never automatically replayed; transfer resume is not supported.
