# QueryCraft 0.1.12

## 中文

- 侧边栏及表总览的表右键菜单增加重命名、删表、截断、清空、重置自增和指定自增值，统一提供 SQL 预览、安全锁、表名确认及操作后刷新。MySQL、PostgreSQL 支持六项操作；Doris 提供重命名、删表和截断，其余项说明限制。Redis、Elasticsearch、Kafka 保留各自的对象操作。
- 修复 MySQL、PostgreSQL 在 `SET NAMES` 等语句成功后误报事务状态的问题，按服务器响应处理事务、保存点及 DDL 隐式提交；MySQL/Doris 共用新版 V3 transport，支持新旧驱动独立升级。
- MCP 设置改为直接页签、对齐的权限操作及独立对象范围弹窗，保留原有权限上限和策略。Dev 的名称、客户端注册、组件渠道及 Skill 安装目录与正式版隔离。
- 主程序移除独立 MCP 的 SDK、HTTP 与 NIO 传输依赖；MCP 改为独立运行包。Intel 与 Apple Silicon 分别下载签名 XZ 更新包，DMG 使用无损 ULMO 压缩，保留原更新源、历史下载、图标及驱动能力。

## English

- Added shared table context actions in the sidebar and object overview: rename, drop, truncate, clear, reset and set auto increment. Actions include SQL preview, Safety Lock, typed table-name confirmation and refresh. MySQL/PostgreSQL support all six; Doris offers rename/drop/truncate with explicit limits for the others. Redis, Elasticsearch and Kafka retain their own object operations.
- Fixed MySQL/PostgreSQL transaction-state errors after successful statements such as `SET NAMES`. Transactions, savepoints and MySQL DDL implicit commits follow server responses. The MySQL/Doris V3 transport supports independent upgrades alongside older drivers.
- Simplified MCP settings with direct tabs, aligned permission controls and transactional object-scope sheets while preserving authorization ceilings and policies. Development names, client registrations, component feeds and installed Skill paths are isolated from production.
- Removed standalone MCP SDK/HTTP/NIO dependencies from the desktop. MCP runs in its own package. Signed native XZ updates and losslessly compressed ULMO DMGs reduce downloads while preserving the existing feed, history, icons and driver capabilities.

三类新驱动仍要求最低主程序 0.1.11；此次表操作通过现有 SQL 执行接口实现，没有修改公共驱动协议。SQL 查询结果不自动重新执行用户语句，表操作刷新对象列表及表数据/结构页。
The three updated drivers retain minimum desktop 0.1.11. Table actions use the existing statement execution API without changing the public driver contract. User SQL queries are not automatically rerun; object lists and table data/structure are refreshed.

## 验证与限制 / Validation and limits

发版前核心、MCP、SQL 执行与表操作的 206 项 Debug 回归通过，零失败、零跳过；17 项组件范围、10 项恢复产物计划、8 项更新归档脚本回归通过。优化 Release 主程序构建通过；正式产物使用 Release 配置。
Pre-release Debug validation passed 206 core/MCP/SQL/table-action tests with zero failures or skips, plus 17 component-scope, 10 recovery-artifact-plan and eight update-archive script regressions. The optimized Release desktop build passed; distribution artifacts use Release configuration.

表操作通过 Debug 编译、36 项逻辑/安全锁/工作区与列表回归、六类驱动加载和会话创建，以及 60 份中英文、明暗原生离屏截图检查。此前事务修复已在 Intel 的 MySQL 5.6/8.4、PostgreSQL 17 实库验证；MCP 设置、签名组件下载/更新/回退、旧会话连续调用及双架构更新包完整性已有本地回归。
Table actions passed the Debug build, 36 logic/Safety Lock/workspace/overview tests, six-driver loading/session creation and 60 Chinese/English light/dark offscreen native snapshots. Earlier transaction fixes were exercised on local Intel MySQL 5.6/8.4 and PostgreSQL 17; MCP settings, signed component installation/update/rollback, old-session continuity and native archive integrity have local regression coverage.

本轮表操作尚未执行实库写入，Docker 未运行；Doris/MariaDB 服务端和真实鼠标键盘操作未验收。PostgreSQL 自增操作针对表所属的 serial/identity 序列，不推测序列名称；设置过低值可能导致后续插入冲突。Doris 的通用 DELETE 清空和自增计数修改禁用。双架构正式产物及原生 MCP/六驱动运行验证由发布流水线执行。
Live writes for the new table actions remain unverified because Docker is stopped. Doris/MariaDB server behavior and physical-input UI acceptance are not claimed. PostgreSQL changes owned serial/identity sequences without guessing names; low values can cause later duplicate keys. Generic Doris DELETE-all and counter changes are disabled. The release pipeline builds both architectures and gates publication on native MCP/six-driver runtime checks.
