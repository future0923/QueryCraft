# QueryCraft 0.1.16

## 中文

- macOS 下载版切换为 Apple Developer ID 签名、公证及可信时间戳，启用 Hardened Runtime，并保留 Library Validation。
- 主程序、独立 MCP、数据库驱动及 SSH 使用同一开发者团队身份验证。原有 Sparkle 与组件目录签名继续保留。
- 凭据助手使用独立的开发者团队安装目录，保留已有连接与旧助手。首次访问旧钥匙串项目可能需要本人重新授权；拒绝或失败不会清空已保存凭据。
- 为原生 iOS/iPadOS 工程补齐自动签名与归档配置。移动端签名归档及 TestFlight 验收独立进行。

## English

- Move macOS downloads to Apple Developer ID signing, notarization and trusted timestamps, with Hardened Runtime and Library Validation enabled.
- Verify the desktop app, standalone MCP, database drivers and SSH against the same developer team. Retain existing Sparkle and component-catalog signatures.
- Install credential helpers in a separate developer-team directory while retaining connections and previous helpers. Access to older Keychain items may require user authorization; denial or failure does not clear saved credentials.
- Configure automatic signing and archives for the native iOS/iPadOS project. Signed mobile archives and TestFlight acceptance are verified separately.

Retain historical catalogs and packages; older self-signed hosts must not select the new Developer ID packages. MySQL/Doris still require separate loading and mixed-version compatibility checks.

## 验证与边界 / Validation and limits

历史本机隔离验证已通过 Intel 主程序、MCP、七类驱动与 SSH 的 11 项 Apple 公证，以及票据、Gatekeeper、七驱动加载、MCP stdio/HTTP 和临时凭据回归。共享核心回归 96 项通过。移动端 arm64 Release 已完成未签名编译。
Earlier isolated local validation passed 11 Apple notarizations for the Intel app, MCP, seven drivers and SSH, plus ticket, Gatekeeper, seven-driver loading, MCP stdio/HTTP and temporary-credential checks. All 96 selected shared-core regressions passed. The mobile arm64 Release build passed without code signing.

上述证据不代表本版本双架构 CI 或正式发布已完成。签名移动归档/IPA、TestFlight、ARM 原生执行及真实旧用户钥匙串授权/升级仍须单独验收；本轮未穷尽七类服务的实库认证/TLS 组合。首次发布须先备齐双架构签名公证组件，再切换主程序与线上目录，禁止覆盖历史资源。
These results do not establish completed dual-architecture CI or publication of this version. Signed mobile archives/IPA, TestFlight, native ARM execution and real legacy-user Keychain authorization/upgrades require separate acceptance. Live authentication/TLS combinations across all seven services are not exhaustive. Prepare both architectures of signed and notarized components before switching the desktop release and public catalogs; never overwrite historical artifacts.
