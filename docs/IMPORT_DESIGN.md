# 表右键导入

状态：2026-10-15，已实现并继续完成导入性能专项。主程序构建通过，验证范围及实库限制见下文。

## 交互

表右键选择“导入数据…”，打开原生五步向导：来源 → 选项 → 映射 → 确认 → 执行。目标固定为右键的现有表，窗口显示连接名、数据库和表名，不需要先打开目标数据页。

1. 选择本地文件。
2. 调整格式、编码、分隔符、标题行、数据起止行、NULL、工作表和预览行数。
3. 加载完整文件快照及真实表结构，按精确名称/唯一忽略大小写名称自动匹配。允许跳过字段，预览最多 200 行；显示实际待导入总行数。
4. 确认目标、来源、行数、映射、追加方式和每批行数（默认 500，可设 1～10000），查看首行 SQL 示例（预览值可能截断）。
5. 点击“开始导入”后真实写入，显示已处理行数、提交结果和失败信息。导入结束后通过主窗口公共刷新按钮查看数据。

右键导出仍是选四格式直接保存，未改成导入向导。

## 文件与数据语义

| 格式 | 支持及边界 |
| --- | --- |
| CSV / TSV / 分隔文本 | 单字符分隔符、双引号转义、引号内换行；UTF-8/BOM、GB18030/GBK、UTF-16 LE/BE；严格检查字段数量与标题重复 |
| JSON / JSONL | 单个对象、对象数组、数组行、QueryCraft 表格结构；数字使用原始词法文本，避免 Double 舍入；嵌套对象/数组保留 JSON 文本；重复键报错 |
| XLSX / XLSM | 选择工作表；共享字符串、内联/富文本、稀疏单元格、日期及时间；读取公式缓存，不执行公式或宏；错误单元格、缺少公式缓存、累计时长等显式报错 |
| SQL INSERT | 同一来源表、相同字段列表、INSERT INTO … VALUES 字面量；接受事务包装和 QueryCraft 的文本转义；解析为数据后重新映射到目标表，不执行原始 SQL |

旧版 XLS 需先另存为 XLSX。SQL 不支持建表、DELETE、REPLACE、INSERT IGNORE、SELECT、任意表达式或冲突更新；不把这些语句悄悄变成普通追加。

默认保留空字符串和前后空白。CSV/TSV 仅把未加引号的 `NULL` 转为 NULL，Excel 按单元格文本匹配；可修改或清空 NULL 标记。JSON/SQL 的原生 null/NULL 保留。JSON 对象的行号从第一条数据记录开始，数组行可以选择标题行。

Excel 需要区分数据库 NULL 与文字 `NULL` 时，导出设置选择 NULL 为空单元格，并在导入时清空 NULL 标记；已导出为同一文本的两种值无法事后区分。CSV 精确回灌应在导出设置关闭公式防护，该选项会有意添加前导单引号。

确认使用解析时的不可变数据快照，执行不重新读取可能已变更的文件。导入不设置应用层文件大小、数据行或单元格数量上限；CSV/TSV、JSON/JSONL 和 SQL 使用 64 KiB 输入窗口，UTF-16/GB18030 先流式转码到 UTF-8 临时文件；XLSX 按 ZIP/ZIP64 目录定位读取，分块解压并用 XML 输入流解析，共享字符串使用磁盘索引和有界缓存。结果超过约 4 MiB 后切换到自有临时磁盘快照（这不是文件大小限制），执行及预校验按批读取。实际规模受内存、暂存磁盘空间、数据库能力和事务时长影响。Excel 仍遵守 OOXML 自身的行列地址范围。Excel 中已经被软件舍入过的数值无法恢复；字符型数字保持原样。

## 写入与取消

- MySQL InnoDB、PostgreSQL 支持。其他 MySQL 引擎不承诺事务回滚，因此本入口明确拒绝执行。
- 读取预览不要求解锁。开始前、连接/结构确认后、每批写入前和提交前检查现有安全锁及捕获的工作区/连接身份。
- 使用选中数据库的独立会话。PostgreSQL 从协议 origin 获取 schema/table，不依据显示名称猜测。
- 执行时重新核对目标字段与表标识。生成列不可映射，未映射的非空且无默认值字段报错；映射重复、空映射、非空列 NULL 均在写入前拒绝。
- 普通 INSERT 追加，不清空已有数据，不忽略重复键。MySQL 会话启用 STRICT_ALL_TABLES；PostgreSQL identity 显式使用 OVERRIDING SYSTEM VALUE。
- 全部批次位于一个事务中；按设置的每批行数生成 INSERT，不设置应用层语句大小上限。数据库自身的包大小或字段大小限制仍由数据库返回错误。核对数据库返回的受影响行数。
- 提交前失败或取消时尝试回滚，结束后关闭会话。取消等待当前请求返回，不宣称能立即终止数据库执行。关闭按钮在执行期间禁用，可使用取消导入。
- 提交开始后等待提交结果；仅明确成功才显示已导入。提交或回滚响应丢失显示“结果未知”，提示核对目标表后再决定是否重试，不自动重试写入。
- 加载期间保留选项和固定窗口区域；进度及错误位于固定区域，关闭或更换来源后过期加载结果不更新当前窗口。

## 六驱动评估

| 驱动 | 导入入口 |
| --- | --- |
| MySQL | 表右键提供，执行支持 InnoDB |
| PostgreSQL | 表右键提供，schema、identity、生成列按实际元数据处理 |
| Doris | 当前驱动只读，不显示导入入口；现有导出继续可用 |
| Redis | 关系表文件导入不适用，保持既有键值功能 |
| Elasticsearch | 本次不新增索引批量导入，保持既有文档能力 |
| Kafka | 本次不新增消息文件导入，保持既有消息发送功能 |

本次未修改 Driver API 和外部驱动。新增功能位于表右键，数据页和 SQL 查询页原有导出流程保留。

## 验证

2026-10-15 导入专项 38 项测试通过，0 失败、0 跳过。覆盖 CSV/JSON/SQL 分块边界、UTF-8/BOM、GB18030、UTF-16 代理对、精确数字、JSON 动态字段、ZIP64 与共享字符串暂存、CRC 损坏、磁盘快照原文变更隔离、完整长值、取消、事务回滚和窗口挂载。

左右表格采用 AppKit NSTableView；右侧复用主数据页的 WorkspaceDatabaseDataRowView，只绘制可见行列，单行 Core Text 排版有界缓存，不再创建逐单元格文本控件。左侧 NSPopUpButton 只在打开时建立完整菜单，字段映射变化只更新对应行，右侧预览不重载。非显示窗口中以 1000 个映射字段、200 行×78 列预览验证控件复用和左右独立滚动。界面最多保留 200 行、每单元格 512 字符的预览；导入保留原始完整值。确认页的 SQL 示例基于有界预览，不在 SwiftUI body 内读取磁盘或构造完整首批 SQL。

独立优化构建的合成 SQL 测量：28311×78（61.5 MiB）解析暂存约 3.86 秒；300000×78（651.7 MiB）约 35.31 秒，峰值 RSS 约 108.7 MiB。该测量包含解析与快照建立，未包含数据库写入、主程序常驻资源或交互帧率，不能据此宣称整个软件没有卡顿。复现脚本为 `scripts/benchmark-data-import.py`。

MySQL 8.0/8.4、PostgreSQL 17 的当前四格式长值磁盘快照回灌均逐字段一致，失败/取消整笔回滚。共享表格绘制改动后的完整 Feature 回归为 1232 通过、0 失败、3 项未配置 Elasticsearch 实库测试跳过（83.8 秒）。Doris 之前的四格式导出与六类驱动评估、实库及显示窗口性能证据详见 [DATA_TRANSFER_VALIDATION.md](DATA_TRANSFER_VALIDATION.md)。极端长中文/emoji 宽表横向滚动仍有掉帧，不承诺所有场景 60 fps。

本次不含新建表、多文件批量建表、清空后导入、忽略/覆盖冲突。大文件在进入映射页前仍需完成快照解析，耗时随文件内容和磁盘性能变化；流式解析避免文件体积等量驻留内存，但仍需容纳单条记录、当前批次与行索引。本次完成导入链路的性能专项，不代表全软件性能普查。
