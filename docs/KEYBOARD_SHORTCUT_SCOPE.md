# macOS 快捷键作用域

菜单可见不代表按键应在整个窗口生效。没有当前上下文或操作不可用时，同时禁用菜单项并移除其 `KeyboardShortcut`，避免禁用菜单继续拦截原生文本编辑按键。

| 上下文 | 命令 |
| --- | --- |
| 当前工作区窗口 | 新建/关闭/切换内容标签、切换连接、打开数据库、公共刷新 |
| SQL 或 Elasticsearch 请求编辑器获得焦点 | 保存查询、运行、停止、格式化；事务命令另受会话能力和状态限制 |
| 当前对象详情区域 | 数据/结构/索引等详情标签、打开筛选 |
| 筛选区域 | 添加、移除、应用、启停和关闭筛选；输入值时保留原生方向键导航及选择 |
| 表格/结构网格 | 增加、复制、删除行；文本输入时不注册行操作按键 |
| 数据编辑区域或检查器 | 提交、预览、放弃当前更改 |
| 结果网格 | 查找、导出；不从 SQL 编辑器回退到最近可见网格 |

`⌘←/→`、`⇧⌘←/→` 等文本导航交给当前文本编辑器。`⌘S` 在查询编辑器内保存查询，在存在可提交更改的数据编辑区内提交更改；`⌘I` 按焦点分别格式化、增加行或增加筛选条件。

原生 CodeEdit 编辑器不完整参与 SwiftUI 焦点值传播，使用它自身的 `NSWindow.firstResponder` 身份控制查询命令。普通视图继续使用 `focusedValue` 限定区域；原生事件监听器另检查焦点、文本输入类型及精确修饰键组合。AppKit 共享 field editor 时，窗口更新后重新检查实际输入控件；几何范围取控件 bounds 与 visibleRect 的交集。

## 驱动范围

- MySQL、PostgreSQL、Doris 共用 SQL 编辑器、表数据、查询结果和结构编辑链路。
- Elasticsearch 请求编辑器单独识别原生文本焦点；文档网格使用公共筛选、查找、导出及编辑命令。
- Redis 键详情、新建键及检查器使用各自的编辑上下文。
- Kafka Topic 详情与配置编辑使用对象详情上下文；不提供 SQL/筛选能力的页面不注册相关按键。
- Milvus 只读 Collection 浏览沿用公共网格；不产生 SQL、事务或可写单元格命令。

这次改动不涉及外部驱动协议或二进制。回归验证使用公共 UI、原生编辑器和内存动作，不执行实库写入；不能据此宣称所有驱动均完成实库界面验收。
