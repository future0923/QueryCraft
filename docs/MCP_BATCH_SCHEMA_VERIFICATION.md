# MCP 批量输出与结构上下文验证

日期：2026-10-30。范围：反馈第 1、2、4 项。第 3 项事务内 DDL 限制保持原行为。

## 行为与边界

- `execute_batch` 默认返回执行计数、失败摘要、事务状态和短期 `batch_id`；错误停止时摘要在 `error.details` 中。执行成功计数不代表提交或持久化，提交回执丢失时状态为 unknown。
- `get_batch_results` 在同一运行时内分页读取已有明细，不建立数据库连接、不执行 SQL；检查原连接完整配置、数据库、完整权限快照及两个工具的授权。明细不进入历史或磁盘，10 分钟、16 批、32 MiB 总量和 8 MiB 单批上限，可能提前淘汰。
- `get_schema_context` 的 compact/detailed 均提供表分页；默认完整名称排序，显式表清单保留请求顺序。紧凑模式不把下一张未完整展示的表计为完整表；超大首表标记 incomplete_tables，提示 describe_table。目录变化后应从首页重新读取。
- 表注释来自详情或现有 SQL 对象总览。使用完整对象 ID（类型、schema 和名称）匹配，不按显示短名或 DDL 猜测。缺失元数据如实为空或 null。
