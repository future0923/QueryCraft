# 编辑器语法配色设计与实施计划

目标：修复 SQL 同类标识符着色不一致，并提供浅色、深色独立保存的语法配色与内置主题。

## 选择与范围

采用“内置主题 + 每种外观的逐项覆盖”。相比只换整套主题，此方案允许细调；相比导入任意主题文件，范围更明确，默认值和升级兼容性更可控。内置经典、海洋、柔和三种风格，每种均提供浅色和深色版本。切换预设清除当前外观的覆盖，另一外观不变；界面明确说明此行为。

设置入口位于现有“编辑器”页的“自定义配色…”按钮，打开原生独立面板。左侧选择编辑浅色或深色（不切换整个应用外观）、内置主题以及 SQL / JSON 预览；左侧预览保持可见，右侧颜色分类使用原生分组表单独立滚动。颜色使用原生 ColorPicker（禁用透明度），显示十六进制值；每行可恢复所选预设颜色，另提供恢复当前外观和现有编辑器整体恢复。

分类：普通文字、关键字、对象名、字段/JSON 键、函数、数据类型、字符串、数字、布尔值/NULL、变量/别名、参数、修饰符、运算符、标点、注释；以及背景、当前行、选区、光标。选区采用固定透明度，颜色选择器设置底色。

## 数据与渲染

新增 EditorColorSettings 值模型，分别存储 light/dark 的 preset 与覆盖字典。使用 Codable + UserDefaults；颜色持久化为标准 sRGB 六位 HEX，非法条目忽略，未知预设回退经典，不让损坏配置阻断启动。ApplicationPreferences 负责保存和观察；主题工厂接受设置值，所有 CodeEdit SQL / Elasticsearch / JSON 界面共用。

保留现有 EditorTheme 初始化兼容性，以可选捕获样式覆盖扩展独立分类。修改配置通过现有 configuration 更新链路重新着色，不重新创建文本视图，避免丢失选区、撤销和滚动。

SQL 修复先以截图中的 ADD INDEX 字段列表复现。正常 AST 继续区分对象名、字段和函数；解析恢复导致的错误分类在语法着色层修正，不改变 SQL 执行、格式化和可靠性判断。保留注释、字符串、引用标识符及 UTF-16 范围安全。

## 驱动与页面评估

| 驱动 | 适用页面 | 数据链路 |
| --- | --- | --- |
| MySQL / PostgreSQL / Doris | SQL 查询与片段编辑器 | 共享 SQL 解析/高亮，无驱动协议变更 |
| Elasticsearch | 请求编辑器、JSON 文档/详情/预览 | 请求行高亮与共享 JSON 编辑器 |
| Redis | 使用共享 JSON 组件的值视图 | JSON 配色；普通文本值不冒充 SQL |
| Kafka | 使用共享 JSON 组件的消息/详情 | JSON 配色；无 SQL 编辑器 |

表格、结果数据单元格不是语法编辑器，本次不改变其字体颜色。外部驱动和 Driver API 无修改，不需重新打包。实库查询与配色无耦合，不以纯 UI 测试冒充实库验证。

## 语法覆盖审计

按用户要求扩充 55 组语法样例：38 组 SQL、9 组 JSON、8 组 Elasticsearch 请求；另有 4 组逐字符输入/删除过程，对比完整重解析结果。所有标记同时检查完整范围与局部刷新范围，中文/emoji 按 UTF-16 索引验证。新增异步旧结果拦截测试。

修复范围：

- SQL：CTE 名称/输出列、schema/database、约束和索引名称、外键引用列的分类；`::` 运算符；科学计数法、十六进制/二进制/八进制及数字分隔符；不完整字符串和注释的显示恢复。

- JSON：修复上游 v0.24.8 对 `1e+3` 和完整 `\\uXXXX` 的识别，保留语法源和可重复生成脚本；未闭合对象中的已完成键继续按字段色显示。
- Elasticsearch：参数名/数值/布尔值/字符串/分隔符分类，注释行、多请求正文排序、各正文独立解析、错误路径与未闭合正文隔离、CRLF、UTF-16 偏移及旧异步结果拒绝。

覆盖页面与驱动沿用上方矩阵：MySQL/PostgreSQL/Doris 共享 SQL；Redis/Kafka 共享 JSON；Elasticsearch 请求及 JSON。只测试本地解析和渲染，不执行样例中的 SQL 或真实请求；无 Driver API 或外部驱动二进制变更。

已知边界：共享 SQL 语法目前没有数据库方言/SQL mode 输入。裸双引号表达式在 MySQL 可为字符串、PostgreSQL 为列名，因此 `SELECT "name"` 仍沿用字符串分类；带限定符的 `u."name"` 按字段识别。此次不以全局替换破坏另一方言，也不宣称任意存储过程或方言扩展均完整支持。
