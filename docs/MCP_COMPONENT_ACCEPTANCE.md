# 独立 MCP / Skill 人工验收

## 前置条件与当前状态

本次已完成 Intel Debug 的自动化隔离验收。生产后台及首批组件尚未部署发布，不能把当前线上下载失败认定为已经通过；现有用户安装保持不变。

人工验收需先准备：新版 LicenseServer、提供 `/components/` 的 HTTPS 下载服务、由受信发行密钥签名的 MCP/Skill ZIP 与 `.release.json`、双语发布说明，以及管理员和只读管理员账号。使用专门的测试数据库连接和已安装驱动，保持只读权限；不要使用生产写入数据。

最新签名主程序位于 `.build/mcp-independent-compatible-20261015/QueryCraftDev.app`。退出旧的 Dev 主程序后从此路径启动，确认只使用该实例。当前任务没有自动替换正在运行的版本。

## 升级与回退

有两个真实兼容发行版本时再人工执行本节；只有首版时标为“未测试”，不要为了验收无代码改动的版本而增加版本号。

1. 保持旧版 stdio 会话和 HTTP 服务各有一个连接。主程序退出后，用固定入口运行 `--update --data-dir <测试数据目录>`。预期新客户端使用新版，旧 stdio 会话仍能完成工具调用；HTTP 按保存的端口和令牌重启。
2. 运行 `--rollback --data-dir <测试数据目录>`，预期恢复兼容的上一版本。授权、连接、历史不应被重置。
3. 运行 `--update-skill --skill-destination <隔离目录>/querycraft --data-dir <测试数据目录>`。预期按当前 MCP 选择兼容 Skill；MCP 回退导致原 Skill 不兼容时允许恢复兼容版本，对仍兼容的 Skill 不自动降级。

运行 `python3 scripts/test-component-release-plan.py`，预期 14 项通过。仅主程序/MCP/Skill 或驱动测试改动不应增加未改驱动的版本/build；只改驱动版本/build 必须失败；共享 transport/API 变更必须选择对应组合；复用旧 run 不得上传残留的无关驱动包。
