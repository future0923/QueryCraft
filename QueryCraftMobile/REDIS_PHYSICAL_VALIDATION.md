# iPad / iPhone Redis 专项真机验证 — 2026-10-27

此前的117项是整个移动端的验收，未包含 Redis 全部专项。本轮单独扫描全部 `MobileRedis*Tests.swift`，发现 **14个套件、59条测试声明**，全部作为真机执行目标；不把先前移动端总数当作 Redis 全量结果。

设备：“魏崃的 iPad Pro”，iPadOS26.5，UDID `00008112-001969510E08201E`。应用沿用原标识、图标和用户数据；服务全部为本轮独立创建、带所有权标签的临时 Redis，iPad 通过 Wi-Fi 直连 Mac 的局域网映射端口。

## 夹具与证据

使用 `scripts/test-redis-physical.py` 动态发现全部套件，校验实际服务器版本和 HPTTL 能力后执行。共享 Redis 测试配置通过 `PROOF_SERVER_HOST` 指向临时服务，不读取设备保存密码，也不保存测试连接。

首轮7.4成功后发现测试夹具的成功清理依赖当前逻辑库，跨库用例结束在DB1时会漏清DB0的一条TTL键。容器当轮已整体删除；夹具改为显式清DB0和DB1，7.2后续运行及7.4受影响写入套件复核均确认全部逻辑库无残留。没有把测试夹具修正表述为Redis业务功能缺陷。所有本轮临时容器都已按所有权标签校验并删除。

曾尝试的本地 Redis Stack 镜像实际是7.4.2，能力校验将其拒绝，未当作旧版结果；之后使用真实Redis7.2.7。另一次Wi-Fi目的地忙/重连的运行执行0条测试，未计为通过。所有历史报告与容器清理回执保留。

证据位于 `.build/ipad-redis/`：

- `74-initial/`：首轮59/0/0及容器销毁。
- `72/`：58/0/1、服务器能力、空keyspace和容器销毁回执。
- `74-connection-timeout/`：目的地超时、零测试。
- `legacy-image-rejected/`：错误候选版本的拒绝与清理。
- `74/`：额外全量重查因Wi-Fi目的地忙执行0条，不能计为通过；所属容器已清理。
- `74-cleanup-focused/`：修正后受影响的12条写入用例通过、空keyspace、容器销毁回执。
- `normal-launch-final.json`：结束后恢复无测试环境的普通App启动。

7.4和7.2均导出测试附件（各2份，包含真实Hash原生输入及清理），保存于对应运行目录的 `attachments/`。页面/状态断言通过不等于人工检查了每一种触控、键盘和屏幕组合。

## 范围边界

“全部”指当前仓库的全部Redis专项套件，不能推导为穷尽所有Redis命令、服务器版本和环境组合。真实手指/外接键盘/第三方输入法、真实断网/系统强杀、保存凭据全矩阵和长期压力没有在本轮穷尽；移动端现有TLS、集群重定向、模块类型等边界仍按原功能限制，不能用本轮通过数证明这些能力已移植。59条与先前117项存在重叠，不累加成唯一用例数量。
